# RoundTable 3D

3D-комната в браузере для учёбы, работы и игр: круглый стол на 8 мест, свои персонажи, голос и видео, чат, общая доска, слайды, демонстрация экрана и настольные игры.

## Что умеет

- **Вход:** гостем, по почте и паролю или через Google (Firebase Auth). Без ключей Firebase работает гостевой режим.
- **Персонаж:** голова (человек, робот, шлем), цвет кожи, причёска и цвет волос, одежда и её цвет, аксессуар (очки, наушники, кепка, корона, бантик). Менять можно на экране входа, в лобби («Изменить персонажа») и прямо за столом (иконка в верхней панели). Изменения сразу видят все.
- **Комната:** код из 6 символов и ссылка-приглашение, рассадка с анимацией, список участников слева (кто говорит, рука, главный, микрофон, камера, статус в игре), чат, реакции, поднятая рука.
- **Голос и видео:** WebRTC каждый с каждым; видео — на экране над стулом, громкость — пульсирующее кольцо у стула.
- **Объяснения (кнопка «Доска, экран и слайды»):** управляет главный, остальные видят то же самое. Показ выводится на большой экран на стене зала и разворачивается на весь экран.
  - **Доска:** перо, 6 цветов, 3 толщины, ластик, отмена, очистка. По умолчанию рисует только главный, он может разрешить рисовать всем.
  - **Слайды:** PDF или картинки (до 40 слайдов), листание стрелками у главного.
  - **Экран:** главный показывает окно или весь экран.
- **Игры (кнопка с геймпадом):** любой участник предлагает игру, главный её начинает. Логика игр работает на сервере: каждый видит только свои карты и роль.
  - **Дурак подкидной:** 2–6 игроков.
  - **Пиковая дама:** 2–8 игроков.
  - **Мафия:** 4–8 игроков. Мафия, шериф, доктор; ночью в зале гаснет свет; фазы переключает главный.
  - **Бункер:** 4–8 игроков. Катастрофа, карточки из 7 характеристик, раскрытие по раундам, голосование.
- **Главный:** создатель комнаты. Если он уходит, роль переходит к тому, кто сидит дольше всех.

## Графика и анимации

- **Качество подбирается по устройству** ([src/lib/quality.ts](src/lib/quality.ts)). На компьютере светится неон (bloom), есть виньетка и чёткость до dpr 2. На телефоне и на слабом процессоре (4 ядра и меньше) постобработки нет, dpr до 1.5. Модуль постобработки грузится отдельным файлом и только там, где нужен. Принудительно: `?quality=high` или `?quality=low` в адресе.
- **Модели из Blender** ([public/models](public/models), подключение — [src/scene/Props.tsx](src/scene/Props.tsx)):
  - `chair.glb` — эргономичное кресло с изогнутой спинкой и неоновой полосой цвета сидящего, ~8,7 тыс. треугольников;
  - `plant.glb` — растение в кадке с латунным пояском;
  - `sofa.glb` и `lamp.glb` — зона отдыха: диваны и торшеры-дуги с тёплым светом.
  - `avatar.glb` — персонаж из частей (узлы `P_*`): торс в трёх вариантах одежды, три головы (человек с лицом, робот, шлем), пять причёсок, пять аксессуаров, рука с кистью, бедро, голень с ботинком. Начало координат каждой части — в её суставе, поэтому части кладутся прямо в «кости» рига в [src/scene/Avatar.tsx](src/scene/Avatar.tsx) и двигаются прежней анимацией. Материалы `Av*` (`AvBody`, `AvSkin`, `AvHair`…) перекрашиваются редактором персонажа. Обычный персонаж — около 17 тыс. треугольников.
  - Исходник всех моделей — [assets-src/roundtable-props.blend](assets-src/roundtable-props.blend). Начало координат каждой модели в центре на полу, «лицом» к +Z. Материалы названы (`Fabric`, `Frame`, `Accent`, `LampGlow`), код перекрашивает их по имени. Экспорт: glTF 2.0 (.glb), модификаторы применены, без Draco.
- **Процедурные модели**: стол со скошенной кромкой, латунной инкрустацией и светящимся кантом; персонажи с плечами, ботинками, глазами с бликом, бровями и носом.
  - Отражения металла даёт окружение из светящихся панелей (drei `Environment` + `Lightformer`), HDR-файлы не скачиваются.
- **Анимации меню** на GSAP ([src/lib/motion.tsx](src/lib/motion.tsx)):
  - каскадное появление экранов входа и лобби;
  - выезд верхней и нижней панелей, списка участников, чата, панелей игр и доски.
  - Если в системе включено «Уменьшить движение», остаётся только короткое проявление. Если браузер не отрисовывает кадры, через 1,5 с всё показывается сразу.

## Запуск

```bash
npm install
npm run dev
```

Откроется http://localhost:5173; сервер работает на порту 3001, проверка — http://localhost:3001/health.
Мультиплеер: создайте комнату, скопируйте ссылку и откройте её во второй вкладке или окне инкогнито.
Камера, микрофон и демонстрация экрана работают только на `localhost` или по HTTPS.

Проверки:

```bash
npm run typecheck
npm run test:games
npm run build
```

`npm run test:games` работает при запущенном сервере: 4 клиента доигрывают все 4 игры до конца.

## Firebase (вход по почте и Google)

1. Создайте проект в [консоли Firebase](https://console.firebase.google.com) и добавьте веб-приложение.
2. **Authentication → Sign-in method:** включите **Anonymous** (для входа гостем), **Email/Password** и **Google**.
3. Скопируйте `.env.example` в `.env` и вставьте ключи из **Project settings → Your apps**.
4. Перезапустите `npm run dev`.

После этого сервер проверяет Firebase ID-токен каждого подключения: без входа в комнату не пустит. Для проверки достаточно `projectId`, ключ сервисного аккаунта не нужен. Для продакшен-домена добавьте его в **Authentication → Settings → Authorized domains**.

## Архитектура

```
roundtable-3d/
├─ shared/                    общее для клиента и сервера
│  ├─ types.ts                Profile, Appearance, Participant, StageState, Stroke
│  ├─ protocol.ts             типизированные события Socket.io, лимиты, варианты внешности
│  └─ games.ts                каталог игр, карты, то, что каждый игрок видит в игре
├─ server/
│  ├─ index.ts                комнаты, рассадка, чат, роли, сцена, доска, слайды, игры, сигналинг WebRTC
│  ├─ auth.ts                 проверка Firebase ID-токена (если задан projectId)
│  └─ games/                  engine.ts (интерфейс, колода), durak, pikdama, mafia, bunker
├─ scripts/smoke-games.mjs    смоук-тест игр
└─ src/
   ├─ lib/                    auth (Firebase), socket, rtc (голос, камера, экран), media, board (холст доски), slides (PDF/картинки → JPEG), seats
   ├─ store/                  useAppStore (вход, профиль), useRoomStore (комната: действия → emit, события → состояние)
   ├─ screens/                AuthScreen, LobbyScreen, RoomScreen
   ├─ scene/                  Loft (зал, ночной режим), Furniture, Avatar (персонаж), StageScreen (экран на стене), Effects, RoomCanvas
   └─ hud/                    TopBar, ControlBar, Roster, SidePanel (чат), StageOverlay, GamesPanel + games/*, CharacterEditor/Modal, Toasts
```

**Как это устроено:**
- **Состояние комнаты:** источник правды — сервер. Клиент шлёт действия, сервер рассылает изменения.
- **Игры:** сервер вызывает `view(state, игрок)` и отправляет каждому участнику его собственную версию: свои карты и роль видит только он.
- **Доска:** штрихи хранятся в нормированных координатах, точки отправляются пачками раз в 40 мс. Новичок получает всю доску при входе.
- **WebRTC:** у каждого соединения три канала — голос, камера, экран. Включение и выключение — через `replaceTrack()`, без повторного согласования.
- **STUN/TURN:** STUN — публичный Google. В сетях за строгим NAT нужен TURN, его задают через `VITE_ICE_SERVERS` (см. `.env.example`).

**Ограничения:**
- Комнаты хранятся в памяти сервера: перезапуск их сбрасывает.
- При соединении «каждый с каждым» каждый отправляет своё видео до 7 раз; для больших комнат нужен SFU (LiveKit, mediasoup).

## Отладка

В dev-режиме в консоли браузера доступны `__room.getState()`, `__three` (R3F), `__rtc()` (соединения WebRTC) и `__level(id)` (громкость участника).
